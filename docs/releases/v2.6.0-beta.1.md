# v2.6.0-beta.1 - Cross-Platform Focus and Security Preview

Release-candidate date: 2026-10-10

Status: Pre-release. Windows 11 x64 and Arch Linux x64 are the supported test
platforms. This build is intended for controlled testing before a stable release.

## Highlights

- One local Go service now provides DNS filtering, the dashboard/API, storage,
  and operating-system controls on Windows 11 and Arch Linux.
- The Avalonia desktop client provides a dark native control surface on both
  supported platforms.
- Focus Capsules connect Discipline goals and tasks to an application allowlist,
  allowed websites, YouTube channel boundaries, local activity evidence, crash
  recovery, and an optional AI Session Coach review.
- The existing Hard System browser extension now performs both local webpage
  risk checks and Focus Capsule browser enforcement.
- Arch packages include a systemd service, DNS routing, diagnostics, safe
  update backups, Connection Freeze, and cgroup v2 plus nftables app controls.

## Added

- Discipline Task Hub, Daily Journal, Focus Activity Logger, Focus Capsules, and
  Intelligence Inbox.
- Vault-protected AI provider configuration for OpenAI, xAI/Grok, Gemini, and
  trusted OpenAI-compatible services.
- Security Center, encrypted DNS, DNS-bypass checks, emergency lockdown,
  signed security packs, Download Guardian, Hard System, and configuration Vault.
- App Network Control and Connection Freeze for Windows and Arch.
- Plugin Center with managed local API runtimes, native controls, sandboxed
  local web views, and the TinyPrinter integration.
- Safe Windows update/uninstall flows and Arch install/update/uninstall scripts.
- Versioned release metadata, SHA-256 checksums, release audits, and health checks.

## Changed

- Linux support is intentionally limited to Arch and Arch-based distributions
  during this release phase.
- The desktop interface is Avalonia-based. The browser dashboard remains the
  complete administration surface and is served only by the local service.
- The browser extension discovers the owner of the active YouTube video rather
  than unrelated channels shown in recommendations.
- Focus history now records the selected capsule and learned YouTube channel.

## Fixed

- Focus sessions survive dashboard refreshes and recover after a service restart
  while their planned time remains valid.
- Temporary application allowlist rules have rollback and expiration cleanup.
- Failed app-rule cleanup is shown to the user instead of being silently hidden.
- Persisted wildcard exceptions, application rules, Vault state, and local data
  survive supported update and restart paths.

## Installation

- [Windows 11 x64](../installation/windows/README.md)
- [Arch Linux x64](../installation/arch/README.md)
- [Hard System browser extension](../../extensions/hard-system/README.md)

There are no default credentials. A new installation creates an administrator
account and a separate Secure Vault during first-run setup. Save both recovery
credentials offline.

## Known limitations

- This is a beta release and is not a replacement for antivirus software, system
  updates, a VPN, or a tested backup strategy.
- Arch ARM64 is a build target but has not been validated on a real device.
- Connection Freeze and per-app network enforcement must complete the documented
  real-machine tests before they are considered production-ready on Arch.
- DNS observations show domain lookups, not the exact encrypted page contents or
  proof that the user actively viewed a page.
- Focus Capsule browser enforcement requires the unpacked Hard System extension
  to be loaded and refreshed after extension updates.
- AI features contact only the provider explicitly configured by the user. The
  deterministic local fallback remains available without an AI provider.

## Recovery

Windows, from an Administrator PowerShell:

```powershell
.\dns-filter.exe reset-app-network
.\dns-filter.exe reset-dns
```

Arch Linux:

```bash
sudo /opt/dns-filter/dns-filter reset-app-network
sudo /opt/dns-filter/dns-filter reset-dns
sudo systemctl restart dns-filter.service
```

Normal uninstall preserves local configuration and data. Permanent deletion is
an explicit separate action documented in the platform installation guide.
