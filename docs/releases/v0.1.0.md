# v0.1.0 - First Public Windows Release

Release date: 2026-10-14

Status: First public release. Windows 11 x64 is the primary verified target.
Arch Linux support remains available for testing, but this package is the clean
Windows portable distribution.

## Highlights

- Local DNS filtering for dangerous websites, advertisements, trackers, adult
  content, and custom rules.
- Real-time dashboard, activity logs, connection analytics, Network Test,
  Download Guardian, Security Center, and explainable blocking decisions.
- Per-application network controls, Connection Freeze, Hard Security, Secure
  Vault, emergency recovery, and persistent notifications.
- Discipline workspace with tasks, projects, habits, journal, Focus sessions,
  Focus Capsules, local activity evidence, Intelligence Inbox, and optional AI
  reviews.
- Avalonia desktop control surface and local browser dashboard.
- Plugin Center with managed local API plugins and the TinyPrinter integration.

## Windows portable controls

The release includes one command entry point:

```powershell
.\dnscli.cmd -S -E   # start, wait until ready, then enable protection
.\dnscli.cmd -D -T   # restore automatic DNS, then stop
.\dnscli.cmd -I      # install
.\dnscli.cmd -U      # safe update
.\dnscli.cmd -X      # uninstall while preserving user data
.\dnscli.cmd -F      # emergency DNS fallback
```

## Privacy and safety

- The service and dashboard run locally.
- DNS Filter is not a replacement for antivirus software, operating-system
  updates, a VPN, or backups.
- AI features contact only the provider explicitly configured by the user.
- Normal uninstall preserves configuration and user data.
- Emergency recovery restores automatic Windows DNS if the service cannot start.

## Installation

Read the [Windows installation guide](../installation/windows/README.md), extract
the ZIP, and use `dnscli.cmd -I` or the included installation launcher.

## Known limitations

- The Windows package is unsigned unless it is built with an Authenticode
  certificate. Windows may show an unknown-publisher warning for an unsigned
  development build.
- Browser Secure DNS / DNS-over-HTTPS must be disabled when the user wants the
  browser to follow Windows DNS routing.
- Some enforcement and recovery controls require Administrator permission.
- Arch Linux support is still considered a separately tested platform rather
  than part of this Windows artifact.
