# Slide Plan and Demonstration Script

## Recommended 15-slide presentation

1. **Problem:** DNS, connections, files, and productivity controls are normally scattered.
2. **Vision:** one local, explainable control center.
3. **Architecture:** Go service, SQLite, web dashboard, desktop app, extension.
4. **Overview:** protection posture and key analytics.
5. **Live DNS:** real-time queries and decision inspection.
6. **Rules:** categories, keywords, blocklist, whitelist, wildcard exceptions.
7. **Applications:** DNS bundles and Windows Firewall control.
8. **Connection intelligence:** timeline, baselines, and unseen destinations.
9. **Download Guardian:** identity, signature, score, quarantine, restore.
10. **Automation:** profiles, schedules, learning, automatic response.
11. **Focus and wellbeing:** guard, sessions, and time bank.
12. **Hard Security:** vault, DNS bypass, lockdown, quarantine, signed packs.
13. **Desktop app:** native dark interface and Windows notifications.
14. **Discipline:** tasks, projects, goals, planning, and analytics.
15. **Honest limits and roadmap:** what the product does and does not guarantee.

## Demo order

1. Open Overview and show protection status.
2. Open Live Monitor and generate a DNS query.
3. Inspect a domain in Decision Center.
4. Show a wildcard allow rule and discovered subdomains.
5. Open Connection Timeline and one application's details.
6. Show New Connections and trust one endpoint.
7. Download a test file created after service startup.
8. Review its SHA-256, signature, and risk reasons.
9. Demonstrate quarantine and restore with a harmless test file.
10. Show the vault audit record.
11. Open the native desktop app and repeat essential controls.
12. End with implementation status and limitations.

## Short opening

“DNS Filter began as a local DNS policy tool. It has evolved into a local protection and control platform that explains DNS decisions, observes application connections, isolates network access, analyzes completed downloads, and gives the user reversible actions through both a web dashboard and native Windows application.”

## Short closing

“The product does not promise magical security. Its value is that evidence stays visible: the user can see what happened, why a decision was made, what action was taken, and how to safely reverse it.”

## Presentation safety

- Use harmless test files only.
- Never demonstrate quarantine on system executables.
- Do not show real passwords, recovery codes, private paths, or personal browsing history.
- Explain that risk scores are prioritization signals.
- Label browser/download-source correlation accurately.
